ok i have an idea! so a special object, i.e. one that we implement, is a regular hash map together with some sort of identifier. if we postfix a function with !, its first argument now takes a list starting with a special object, and ending with a sequence of keywords, with the added condition that when you query these keywords one by one, the product is compatible with the original function's type signature. so for example, for special_obj = {:a {:b {:c 1}}}, you can call (inc! [special_obj :a :b :c]). anyways, the function now evaluates and the specific component of the special object is mutated in place, making the special object different. i then cheat at the implementation level, compare the special object before and after the change, and make changes to the object on the actual machine to respect those changes.
for example, i can write (not! [file :perms :u :w]). if the uw bit in file is True, not turns it into false. false is then mutated into that the uw bit in the file. the program compares the two hash maps, and discovers that the uw bit is turned off, so it does its best to respect that, running chmod u-w
